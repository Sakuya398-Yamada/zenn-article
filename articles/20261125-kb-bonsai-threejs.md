## はじめに

Obsidian で個人のノートを書きためている。ノートどうしは `[[リンク]]` でつながっていて、Obsidian のグラフビューで見ると網の目になる。

これを眺めていて、「盆栽の形で 3D にしたら面白いのでは」と思った。ノートが増えると木が育つ。机の上に置いておける。

本記事では、three.js で作ったその「盆栽」の作りと、見た目を 6 回作り直して結局最初の形に戻った経緯をまとめる。作業は Claude Code と一緒に進めた。


## 見立てを決める

最初に決めたのは、ノートのどれを木のどこにするかだ。

| 盆栽 | ノート |
|---|---|
| 幹 | ノート全体 |
| 枝 | フォルダ。ノートが多いほど下で、長く太い |
| 葉のかたまり | ノート 1 件。大きいほど長く、明るいほど更新が新しい |
| 頂の新芽 | 未整理のメモ |
| 落ち葉 | アーカイブ |
| 石 | テンプレートや運用の文書 |
| 糸 | 選んだノートのリンク先・リンク元 |

ノートは約 450 件、リンクは約 1,900 本ある。このうち木に付くのは 200 件ほどで、残りは落ち葉と石になる。

## 作り

全体は 2 つのファイルでできている。

- Python のスクリプト：ノートの frontmatter と `[[リンク]]` を集めて、JSON にする
- HTML 1 枚：その JSON を埋め込んで、three.js（0.170.0）で描く

サーバーは要らない。スクリプトを実行すると、データ入りの HTML が 1 枚できる。ノートの題名が入るので、できた HTML は公開しない。

### 幹と枝：先細りの管を自分で作る

three.js の `TubeGeometry` は太さが一定なので、幹には使えない。`CatmullRomCurve3` で曲線を作り、`computeFrenetFrames` で向きを取って、輪を並べて面を張った。

幹の太さは、位置 `t`（0〜1）の関数にした。根元だけ急に広げると、盆栽らしい「根張り」になる。

```js
const trunkR = (t) => 0.07 + 0.33 * Math.pow(1 - t, 1.3) + 0.38 * Math.exp(-t * 16);
```

### 葉：InstancedMesh と、ひまわりの種の並び

葉のかたまりは、低ポリゴンの球を `InstancedMesh` で描いている。1 件のノートが 1 つのかたまりだ。

枝先の「棚」の中では、ひまわりの種と同じ並び（黄金角ずつ回しながら外へ）で置いた。古いノートが中心、新しいノートが外側になるので、ノートが増えると棚が外へ広がる。

```js
const GOLDEN = 2.39996323;
const rr = R * Math.sqrt((q + 0.5) / k), th = th0 + q * GOLDEN;
```

### 形を変えない乱数

葉の向きや枝のゆらぎには乱数を使う。ただ、`Math.random()` だと開くたびに形が変わってしまう。

そこで、ノートのパスやフォルダ名から乱数の種を作った。同じノートなら、いつ作り直しても同じ場所に同じ向きで付く。

```js
function hash(str) {
	let h = 2166136261;
	for (let i = 0; i < str.length; i++) { h ^= str.charCodeAt(i); h = Math.imul(h, 16777619); }
	return h >>> 0;
}
```

### 育つ動き

日付のスライダーを付けて、その日までに作られたノートだけの木にできるようにした。

工夫したのは、木の形を「数字から毎回作り直す」形にしたことだ。枝ごとに、ノートの数・順位・太さを数字で持つ。日付が変わったら行き先の数字だけを変えて、毎フレーム少しずつ寄せながら形を作り直す。

```js
const k = 1 - Math.exp(-dt * 4.5);       // 1フレームで寄せる割合
g.n += (g.tn - g.n) * k;                 // ノートの数（枝の長さ・太さになる）
g.u += (g.tu - g.u) * k;                 // 順位（枝の高さになる）
```

こうすると、フォルダのノート数の順位が入れ替わったときに、枝が幹に沿ってするすると上下に動く。葉は小枝の根元から芽吹き、落ち葉は頂から落ちてくる。

## 見た目を 6 回作り直した

ここからが本題だ。最初の形（以下「和」）ができたあと、「もっとデジタルな見た目にできないか」と欲が出て、次々に作り直した。

| # | 見た目 | やったこと | 結果 |
|---|---|---|---|
| 1 | ネオン | 葉を結晶にして自分で光らせ、幹に網目を重ね、bloom をかける | 採用 |
| 2 | 白黒の点 | 表面にだけ点を打ち、形は黒く塗って裏の点を隠す | 形が読みにくい |
| 3 | 点＋輪郭線 | 木の形だけを別に描いて、外側のふちを画面の上でなぞる | 読めるが、まだ違う |
| 4 | 白い線 | 幹を網目、葉を葉っぱの輪郭にする | ごちゃつく |
| 5 | 線を簡略化 | 葉を円 1 つに、枝を 1 本線にする | 植物に見えない |
| 6 | 本物らしい木 | 木の生成ライブラリ EZ-Tree で枝ぶりと葉を作る | 本物らしいが、情報が多すぎる |

結局、残したのは最初の「和」と 1 の「ネオン」だけだった。


作り直しの中で、使える技術もいくつか拾えたので、3 つだけ書いておく。

### ネオン：インスタンスの色で光らせる

`InstancedMesh` は、インスタンスごとの色（`setColorAt`）を持てる。ただ、この色は拡散色に掛かるだけで、自分では光らない。

`onBeforeCompile` でシェーダーに 1 行足して、インスタンスの色をそのまま発光に足した。これで「新しいノートほど明るく光る」ができる。

```js
m.onBeforeCompile = (sh) => {
	sh.uniforms.uGlow = m.userData.glow;
	sh.fragmentShader = sh.fragmentShader
		.replace('#include <common>', '#include <common>\nuniform float uGlow;')
		.replace('#include <emissivemap_fragment>',
			'#include <emissivemap_fragment>\n#ifdef USE_COLOR\n\ttotalEmissiveRadiance += vColor.rgb * uGlow;\n#endif');
};
```

あとは `UnrealBloomPass` をかける。輪や糸のように強く光らせたいものは、色を 1 より明るくしておくと、にじみが出る。

最初は彩度の高いシアンとマゼンタにしたが、強すぎた。彩度を落として白に寄せ、そのぶん bloom を強くしたら落ち着いた。

### 点や線で描くとき：黒く塗って裏を隠す

点や線だけで立体を描くと、裏側の点や線も透けて見えて、形が読めなくなる。

効いたのは、形そのものを背景と同じ色で塗っておくことだ。面は見えないが、深度には書かれるので、裏側の点や線が隠れる。面と線が同じ深さで重なってちらつくときは、面のほうに `polygonOffset` を付けて少し奥へ送る。

### 出来合いのライブラリに、外から手を入れる

本物らしい木には [EZ-Tree](https://github.com/dgreenheck/ez-tree)（MIT）を使った。幹 → 大枝 → 中枝 → 小枝と、枝分かれを何段も作ってくれる。

困ったのは、「この葉はどのノートか」を持たせる口が無いことだった。ライブラリを書き換える代わりに、`Tree` を継いだクラスを作って、枝と葉を作る関数を包んだ。

```js
class KBTree extends Tree {
	generateBranch(branch) {
		this.cur = branch;                       // いま作っている枝を覚えておく
		super.generateBranch(branch);
	}
	generateLeaf(origin, orientation) {
		this.kb.leafNote.push(this.noteOf(this.cur));   // この葉がどのノートかを記録する
		super.generateLeaf(origin, orientation);
	}
}
```

大枝をフォルダに、小枝をノート 1 件に割り当てて、葉をクリックするとノートが出るところまでは作れた。

## なぜ最初の形に戻ったか

EZ-Tree の木は、たしかに本物らしかった。葉は 3,000 枚近くあり、風で揺れる。

ただ、見たいのは木ではなく、ノートのまとまりだった。葉が 3,000 枚あると、どれが 1 件のノートなのかが分からない。最初の形は、ノート 1 件が丸いかたまり 1 つなので、数えられる。

模型として見るなら、情報は少ないほうがいい。6 回作り直して分かったのは、それだけだった。

もう 1 つ。見た目の迷いは、技術を替えても減らなかった。点、線、ライブラリと道具を替えるたびに、できることは増えたが、「これだ」という感じは増えなかった。先に「何を見たいのか」を言葉にしておくべきだった。

## おまけ：AR グラスに持っていくなら

この盆栽は、Android XR のグラスで机の上に置くつもりでいる。調べていて、1 つ面白いことが分かった。

光学シースルーのグラスでは、真っ黒が透明になる。Android XR の開発者向けの資料にも、有線の XR グラスについてそう書かれている。

つまり、黒い背景に光で描くネオンの見た目は、そのまま AR 向きの絵作りになっている。逆に、暗い幹や影で見せる「和」は、グラスでは見えにくいはずだ。

WebXR で机に置くところまでは入れたが、実機ではまだ確かめていない。うまくいったら、別の記事に書く。

## まとめ

- ノートのグラフは、フォルダを枝、ノートを葉にすると、盆栽の形にできる
- 乱数の種をノートの名前から作ると、作り直しても形が変わらない
- 形を「数字から毎回作り直す」形にしておくと、育つ動きが楽に作れる
- 点や線で立体を描くときは、形を背景の色で塗って裏を隠す
- 本物らしさと見やすさは別。模型として見るなら、情報は少ないほうがいい
